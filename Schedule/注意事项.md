# 开发注意事项

> 最后更新: 2026-06-01

---

## 🏗️ 架构原则

### 1. 隐私优先
- **加密必须从第一天做起**，不可后期补救
- 所有用户数据在本地加密后再传输
- 后端设计为"无法解密"模式
- 日志中不可出现用户对话内容

### 2. 单对话模型
- 每个用户只有**一个**对话实例
- 无"新建对话"、"历史对话列表"等概念
- 所有设计围绕"一条时间线"展开
- 对话即用户，用户即对话

### 3. AI 回音壁人格一致性
- AI 的人设比功能丰富更重要
- 回应方式必须保持统一风格
- 不评判、不指责、不贴标签是底线
- 即使更新模型版本，人格也不可漂移

### 4. 离线可用
- 核心功能（查看历史、写新记录）应支持离线
- AI 回应在无网络时使用本地模型
- 同步是增强功能，非核心依赖

## 💻 开发规范

### Git 工作流
- 使用 GitHub Flow：`main` → `feature/xxx` → PR → `main`
- commit 信息格式：`type(scope): description`
  - `feat(app): add emotion picker`
  - `fix(server): handle empty message`
  - `docs: update privacy policy`
- 禁止直接 push 到 `main`，除非紧急修复

### 代码风格
- Flutter: 遵循 [Effective Dart](https://dart.dev/guides/language/effective-dart) 规范
- Go: 遵循 [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)
- 所有 UI 文案使用中文（目标用户为中文用户）
- 代码注释和文档使用中文

### 分支命名
```
feature/app-chat-screen
fix/server-auth-nil-pointer
docs/memory-update-0601
chore/ci-android-build
```

## ⚠️ 关键风险

### 加密与隐私
| 风险 | 缓解措施 |
|------|----------|
| 用户忘记 PIN | 提供助记词恢复方案 |
| 加密密钥丢失 | 端到端加密备份 + 用户自行保管密钥 |
| 第三方库漏洞 | 定期更新依赖 + 关注安全公告 |

### AI 安全
| 风险 | 缓解措施 |
|------|----------|
| AI 给出不当回应 | 严格 System Prompt + 内容过滤层 |
| 用户自残/自杀表达 | 检测到高危情绪时显示专业援助信息 |
| 模型偏见 | 多样化测试集 + 定期偏见审计 |

### 技术债务
| 风险 | 缓解措施 |
|------|----------|
| 长上下文导致性能下降 | 提前设计压缩方案，Phase 2 即考虑 |
| 本地模型太慢 | 优先云端，本地作为降级方案 |
| 跨平台兼容性问题 | Flutter 单平台测试通过后再扩展 |

## 📋 团队协作

### 沟通
- 每日同步：5 分钟文字同步进度
- 每周例会：30 分钟，Review 进展 + 调整计划
- 使用 GitHub Issues 追踪任务
- 重要决策记录到 Memory Doc

### 代码 Review
- 所有 PR 需要至少 1 人 Review
- Review 重点：安全性、隐私性、可维护性
- 紧急修复可在合并后补 Review

### 版本管理
- 语义化版本: `v0.1.0`（MVP）, `v1.0.0`（正式版）
- 每个 Release 附带 CHANGELOG
- Tag 与 Release 对齐

## 🎯 用户优先

### 三类目标用户的核心诉求
1. **高敏感人群**: 安全感 > 功能丰富
2. **高表达欲人群**: 分享便捷 > 分析深度
3. **内敛型人群**: 引导清晰 > 界面美观

### 产品原则
- 功能可以少，但已有功能必须可靠
- 每次交互都让用户感到"被理解"
- 不追求 DAU/留存指标，追求"每次打开都有价值"
- 用户数据属于用户，我们只是托管者
