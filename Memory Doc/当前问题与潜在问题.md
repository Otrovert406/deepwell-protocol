# 当前问题与潜在问题

> 最后更新: 2026-06-01

## 🔴 当前问题

### 1. 加密层密钥硬编码
- **文件**: `app/lib/services/encryption_service.dart`
- **问题**: `SecretKey` 的密钥来源为注释 `/* derived from user pin */`，实际未实现 PIN 派生逻辑
- **影响**: 当前所有加密操作不可用
- **解决方案**: 实现 PBKDF2 密钥派生函数，用户首次启动时设置 PIN

### 2. SQLite 未加密
- **文件**: `app/lib/services/storage_service.dart`
- **问题**: 使用标准 `sqflite`，数据以明文存储
- **影响**: 用户隐私无法保障
- **解决方案**: 替换为 `sqflite_sqlcipher` 或类似加密数据库插件

### 3. Flutter 字体 assets 缺失
- **文件**: `app/pubspec.yaml`
- **问题**: 声明了 `NotoSansSC` 字体，但 `assets/fonts/` 目录不存在
- **影响**: App 编译可能失败或使用 fallback 字体
- **解决方案**: 下载 NotoSansSC 字体文件放入 `app/assets/fonts/`

### 4. Go 后端依赖未下载
- **文件**: `server/go.mod`
- **问题**: 声明了 `gorilla/mux` 等依赖，但未运行 `go mod download`
- **影响**: 后端无法编译
- **解决方案**: 执行 `go mod download` 或 `go mod tidy`

### 5. Emotion Picker / Message Bubble 组件
- **文件**: `app/lib/widgets/emotion_picker.dart`, `app/lib/widgets/message_bubble.dart`
- **问题**: 文件存在于目录结构中，但尚未确认是否包含完整实现
- **影响**: UI 交互可能不完整
- **解决方案**: 审查并补全组件实现

## 🟡 潜在问题

### 1. 单对话模型的长期性能
- **描述**: 每个用户只有一个对话，随着时间推移消息数量会极大增长
- **风险**: 本地数据库查询变慢，AI context 窗口溢出
- **缓解方案**: 
  - 定期归档旧消息到分段存储
  - 对话摘要压缩算法
  - 向量检索替代全文搜索

### 2. 本地模型（llama.cpp）在移动端的可行性
- **描述**: 移动设备（尤其是 iOS）的算力和内存限制
- **风险**: 本地推理速度慢，影响用户体验
- **缓解方案**:
  - 优先实现云端 API，本地模型作为可选增强
  - 使用量化模型（Q4/Q5）
  - 仅在 Wi-Fi + 充电时执行本地推理

### 3. OpenAI API 成本
- **描述**: 长上下文 + 高频使用会导致 API 费用快速上升
- **风险**: 项目可持续性受影响
- **缓解方案**:
  - 智能路由：简单回应走本地模型
  - 对话压缩减少 token 消耗
  - 考虑更经济的模型（Claude Haiku / GPT-4o-mini）

### 4. 社交平台 API 限制
- **描述**: 微信朋友圈 / 小红书对外部 App 分享有严格限制
- **风险**: 社交同步功能可能无法实现或需要企业资质
- **缓解方案**:
  - 提前调研各平台分享 API 要求
  - 备选方案：生成分享图片/文案，用户手动粘贴

### 5. 数据迁移与备份
- **描述**: 用户数据存储在本地加密数据库
- **风险**: 用户换设备或卸载 App 会导致数据丢失
- **缓解方案**:
  - 实现端到端加密的云备份（用户自己保管密钥）
  - 本地导出为加密文件

### 6. AI 回音壁的安全边界
- **描述**: AI 可能在某些极端情绪下给出不当回应
- **风险**: 法律责任风险
- **缓解方案**:
  - 定义明确的安全边界 Prompt
  - 高风险情绪检测时提示专业援助渠道
  - 内容过滤层

### 7. 团队协作效率
- **描述**: 2-5 人小团队，可能分布在不同的时区/背景
- **风险**: 沟通成本高，代码冲突
- **缓解方案**:
  - 明确分支策略（Git Flow / GitHub Flow）
  - 定期同步会议
  - 代码 Review 机制
